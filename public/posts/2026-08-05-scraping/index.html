Scraping Dynamic Government Websites with Google Apps Script and Google Sheets#

Many government portals publish useful public information such as financial statements, reports, expenditure details, and audit information. Automating the collection of such publicly available data can save hundreds of hours of manual work.

This article explains how to automate data collection using Google Apps Script and Google Sheets, while also discussing the limitations when dealing with modern JavaScript-based websites.

Note

Always ensure that your data collection complies with the website’s Terms of Service, robots.txt, and applicable laws. Respect server resources by limiting request frequency.

Project Goal#

Suppose we want to collect financial statement information from a dynamic government portal.

Our automation should:

  • Open a webpage
  • Collect available financial data
  • Store the results into Google Sheets
  • Repeat the process automatically every day

Understanding Static vs Dynamic Websites#

Before writing any code, understand how websites load their data.

Static Website#

The HTML already contains the required information.

Example:

<table>
<tr>
<td>Gram Panchayat</td>
<td>₹4,50,000</td>
</tr>
</table>

Google Apps Script can easily read this.

Step 4 — Download HTML#

function downloadHTML() {

  const url = "https://example.com";

  const html = UrlFetchApp.fetch(url).getContentText();

  Logger.log(html);

}

This downloads the webpage source.

Step 5 — Extract Data#

Suppose the HTML contains

<td>Village Panchayat</td>
<td>125000</td>

We can use Regular Expressions.

function extractData() {

  const html = UrlFetchApp.fetch("https://example.com")
      .getContentText();

  const regex = /<td>(.*?)<\/td>/g;

  let results = [];

  let match;

  while ((match = regex.exec(html)) !== null) {

      results.push(match[1]);

  }

  Logger.log(results);

}

Step 6 — Save Data into Google Sheets#

function saveData() {

  const sheet =
      SpreadsheetApp
      .getActiveSpreadsheet()
      .getSheetByName("FinancialData");

  sheet.clear();

  const values = [

      ["Panchayat","Amount"],

      ["ABC Gram Panchayat",50000],

      ["XYZ Gram Panchayat",25000]

  ];

  sheet.getRange(
      1,
      1,
      values.length,
      values[0].length
  ).setValues(values);

}

Step 7 — Automatic Scheduling#

function createTrigger(){

ScriptApp.newTrigger("main")
.timeBased()
.everyDays(1)
.atHour(8)
.create();

}

Now Google automatically runs the script every day.

Step 8 — Complete Workflow#

function main(){

downloadHTML();

extractData();

saveData();

}

Reading JSON APIs#

Many government portals use JSON.

Example response

{
  "district":"Gangtok",
  "gp":"ABC",
  "amount":150000
}

Apps Script can parse it easily.

function readJSON(){

const url="https://example.com/api";

const response=UrlFetchApp.fetch(url);

const json=JSON.parse(response);

Logger.log(json.amount);

}

Limitations of Google Apps Script#

Google Apps Script is excellent for many automation tasks, but it has important limitations when scraping modern web applications.

  • It cannot execute JavaScript running in the browser.
  • It cannot click buttons or navigate interactive interfaces.
  • It cannot solve CAPTCHAs.
  • It cannot handle complex authentication flows without additional work.
  • Execution time is limited for each script run.
  • Daily quotas apply to URL fetch requests and other services.

When a website relies heavily on client-side rendering, Apps Script alone may not be sufficient.

Can It Scrape Dynamic Government Portals?#

The answer depends on how the portal delivers its data.

Website Type Google Apps Script
Static HTML ✅ Yes
Public JSON API ✅ Yes
Server-rendered HTML ✅ Yes
JavaScript-rendered pages ⚠️ Only if the underlying API can be identified
Login with CAPTCHA ❌ No
Interactive Single Page Applications (SPA) ❌ Not directly

The key is to inspect the browser’s Network tab. If the page loads data through a public API returning JSON, Apps Script can often request that API directly instead of attempting to scrape the rendered page.

Best Practices#

  • Respect website terms of use and applicable laws.
  • Use the official APIs whenever available.
  • Add delays between repeated requests to avoid overloading servers.
  • Store raw data separately from processed data.
  • Implement error handling and logging.
  • Use triggers responsibly to avoid exceeding Google Apps Script quotas.

Final Thoughts#

Google Apps Script and Google Sheets provide a powerful, free, and cloud-based platform for automating data collection from many public websites. For static pages or publicly accessible JSON APIs, the workflow is straightforward and requires only a few hundred lines of JavaScript.

However, many modern government portals use JavaScript frameworks, authentication mechanisms, or CAPTCHA challenges that Apps Script cannot handle directly. In those situations, the recommended approach is to identify and use the underlying API if one exists. If no API is available and the data is rendered entirely in the browser, a browser automation framework such as Playwright or Puppeteer is generally more appropriate.

Understanding how a website loads its data is the most important step before choosing a scraping strategy. With the right approach, Google Apps Script can become an effective automation tool for scheduled reporting, data consolidation, and public information analysis.
